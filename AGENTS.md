# Governance agent instructions

Applies to contributions to this repository. Read `README.md`, `standards/project-steering.md`, the relevant existing Ruleset/WordPress standard, and the current issue before any edit.

This public repository contains **portable standards only**. Do not add private portfolio listings, internal hosts, customer names, secrets, unpublished commercial commitments, or assumed production statuses. The private owner portfolio keeps the full cross-repository inventory.

Preserve the existing hard-guardrails, merge-gates, WordPress blueprint and special-case protections. No PR before **exact-head green branch CI**; after PR opening require independent green PR CI and a final merge-tree readback. Do not perform or infer deployments, legal-contract signatures or Ruleset Admin writes from a documentation task.

Project steering applies across all owner-controlled projects, but it **never** replaces a target repository's more specific instructions, issue/priority, security boundaries, CI trigger or release policy. Forks require a separately justified adoption decision; do not edit upstream mirrors blindly.

After a completed scoped task report exact facts and dates, what is still unknown, and the next safe action. A feature branch is not merged policy; documentation is not live status.
